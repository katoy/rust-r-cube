### F1 — P2: 探索中（`solving = true`）のキーボード回転ショートカット発火により、探索が強制中断されキューブ局面が破壊される

- **再現**:
  Korf や時間のかかる探索を実行中（`solving = true`、キャンセルボタン表示中、全回転ボタン `[data-move]` は `disabled`）に、キーボードで `U`, `R`, `F`, `D`, `L`, `B`（または Shift+キー）を押下した。
  画面上の回転ボタンは無効化されているにもかかわらず、キーボード入力が受理され、即座に探索 Worker が強制中断されてキャンセルボタンが消滅し、キューブの 3D 盤面に回転が適用されて局面が書き換わった。実測証跡 [`docs/review-evidence/004290a/probe-ui.json`](review-evidence/004290a/probe-ui.json)（`f1KeyboardMoveDuringSolve`）を参照。
- **原因**:
  [`web/main.ts`](file:///Users/katoy/github/study-rust/rust-r-cube/3x3-web-2/web/main.ts#L795-L797) の `setupKeyboardShortcuts` 登録において、`onPlay` や `onSeek` には `if (solving) return;` のガードが設置されているが、`onMove` にはガードが欠落している：
  ```typescript
  onMove: (move) => {
    void applyAlgorithm(move); // solving の判定がない
  },
  onPlay: () => {
    if (solving) return;
    void play();
  },
  onSeek: (step, animate) => {
    if (solving) return;
    void seek(step, animate);
  },
  ```
  `applyAlgorithm` 内で冒頭に `cancelSearch()` が呼ばれるため、探索中のキー入力で探索が即座に吹き飛んでしまう。
- **先行レビュー（Claude/Codex/Copilot）の見落とし理由**:
  直前のレビュー（`b605038` の F2）で UI ボタンの `disabled` 属性（`[data-move]` への `|| solving` 追加）と、Space / Arrow キーのガードだけを確認し、**同じキーボード操作系統である英字回転キー（`onMove`）に対するガードの非対称性** を完全に点検から漏らしていた。
- **影響と修正案**:
  利用者が探索完了を待つ数秒の間に誤ってキーボードに触れただけで、最大30秒かかる探索が即座に失われ、盤面が破壊される。
  [`web/main.ts`](file:///Users/katoy/github/study-rust/rust-r-cube/3x3-web-2/web/main.ts#L795) の `onMove` に `if (solving) return;` を追加し、探索中のキー入力を無効化する。

### F2 — P2: 探索タイムアウト／エラー発生時に、画面中央のメタ情報に「探索中 · X.X 秒 / 5 秒」というゾンビ表示が永久残留する

- **再現**:
  解法探索を実行し、探索時間の上限（タイムアウト）またはエラーに達した（画面下部に「探索時間の上限に達しました。30秒の延長探索を試してください。」と表示され、`#cancel` ボタンが消えて `#solve` ボタンと `#extended` ボタンが表示された状態）。
  この時、画面中央のメタ情報エリア（`#solver-note`）を検査したところ、探索は既に終了しているにもかかわらず **「探索中 · 0.2 秒 / 5 秒」** と表示されたまま永久に残存した。実測証跡 [`docs/review-evidence/004290a/probe-ui.json`](review-evidence/004290a/probe-ui.json)（`f2ZombieSolverNoteOnTimeout`）を参照。
- **原因**:
  [`web/main.ts`](file:///Users/katoy/github/study-rust/rust-r-cube/3x3-web-2/web/main.ts#L494-L523) の `solve()` は、探索中に `interval = window.setInterval(...)` で 100ms ごとに `#solver-note` を「探索中 · X.X 秒」に更新している。
  探索成功時（L512）には「XX ノードを探索 · 完成を検証」で上書きされ、手動キャンセル時（L98, L603）には「探索を中止しました」で上書きされるが、**`catch (error)` ブロックおよび `finally` ブロックでは `#solver-note` が一切更新されない**。
  そのため、タイムアウトで抜けた際は最後にタイマーが書き込んだ「探索中 · X.X 秒」という進行中ステータスがそのまま居座る。
- **先行レビュー（Claude/Codex/Copilot）の見落とし理由**:
  「探索が正常に完了するケース」および「ユーザーが途中でキャンセルボタンを押すケース」のみをテストし、「探索がタイムアウト（予算超過）またはエラーで自然終了した際の UI メタ表示」を一度も実測していなかった。
- **影響と修正案**:
  探索は停止しておりキャンセルボタンもないのに、画面上には「探索中」と出続けるため、利用者は「まだ裏で探索が動いているのか、終わったのか」を判別できず認知的混乱に陥る。
  [`web/main.ts`](file:///Users/katoy/github/study-rust/rust-r-cube/3x3-web-2/web/main.ts#L515-L523) の `catch (error)` 内で `$("solver-note").textContent = "探索時間の上限に達しました";` 等を設定するか、あるいは `refresh()` 内で `!solving` かつエラー時のフォールバック表示を保証する。

### F3 — P2: 解法プレビューシーク中に「共有リンク」（`#share-link`）を押すと、スクランブル局面ではなくプレビュー途中の局面（完成再生後は完成状態）が共有される

- **再現**:
  スクランブル局面で解法を探索し、解法が表示された後、「最後の手順へ」（`#last`）を押して完成状態までプレビューを進めた。この状態で画面下部の「共有リンク」（`#share-link`）をクリックして生成された URL を取得した。
  URL のクエリパラメータ `?state=...` を検査したところ、ユーザーが解こうとしていた元のスクランブル局面ではなく、**完成状態（`UUUUUUUUURRRRRRRRR...`）の局面が埋め込まれていた**。相手がこのリンクを開いても、すでに揃ったキューブが表示されるだけであり、元のスクランブルは完全に失われていた。実測証跡 [`docs/review-evidence/004290a/probe-ui.json`](review-evidence/004290a/probe-ui.json)（`f3ShareLinkDuringPreview`）を参照。
- **原因**:
  [`web/main.ts`](file:///Users/katoy/github/study-rust/rust-r-cube/3x3-web-2/web/main.ts#L740-L745) の `share-link.onclick` は、無条件に `store.getState()` と `snapshot.centerTurns` を使って URL を生成している。
  プレビュー中（`store.baseSnapshot` が存在する場合）、`store.getState()` はシーク途中の局面を返すため、解こうとしていた元の局面情報が共有リンクに反映されない。
- **先行レビュー（Claude/Codex/Copilot）の見落とし理由**:
  直前のレビュー（`b605038` の F1）では「再探索時」のスクランブルロールバック（`restoreBaseSnapshot`）にのみ着目し、**「プレビューシーク中の共有リンク生成」という別の外部出力経路** における局面すり替えを見落としていた。
- **影響と修正案**:
  解法を確認しながら「このキューブ面白いから見て」と共有した利用者が、完成キューブ（または中途半端な途中の形）を送ってしまう。
  [`web/main.ts`](file:///Users/katoy/github/study-rust/rust-r-cube/3x3-web-2/web/main.ts#L740) において、プレビュー中（解法が存在し、シーク中の場合）は `store.baseSnapshot` の局面およびセンター向きを優先して共有 URL を生成するか、またはユーザーにどちらを共有するか整合性を持たせる。

### F4 — P3: `solve()` 冒頭における `restoreBaseSnapshot()` と `setSolution(undefined)` の二重呼び出しによる重複通知（ダブルレンダリング）

- **再現**:
  解法プレビューシーク後に `solve()` を呼び出した際の内部ストアイベントを監視した。
  同一実行コンテキスト内で `solution` イベントが 2 回連続で同期発火し、高コストな `refresh()`（DOM全走査、ARIAバインディング、スタイル適用）が重複実行された。実測証跡 [`docs/review-evidence/004290a/probe-ui.json`](review-evidence/004290a/probe-ui.json)（`f4DoubleNotificationOnSolve`）を参照。
- **原因**:
  [`web/main.ts`](file:///Users/katoy/github/study-rust/rust-r-cube/3x3-web-2/web/main.ts#L485-L486) で：
  ```typescript
  store.restoreBaseSnapshot();
  store.setSolution(undefined);
  ```
  `restoreBaseSnapshot()`（[`cube-store.ts`](file:///Users/katoy/github/study-rust/rust-r-cube/3x3-web-2/web/cube-store.ts#L189)）が内部で `this.solution = undefined` を設定して `this.notify("solution")` を呼んでいるにもかかわらず、その直後に `store.setSolution(undefined)`（L200）を重ねて呼んでおり、二重に `notify("solution")` が発火している。
- **先行レビュー（Claude/Codex/Copilot）の見落とし理由**:
  不具合 F1 を解消するためのパッチ（`restoreBaseSnapshot()` の挿入）の挙動のみを確認し、既存の `store.setSolution(undefined)` との重複関係・ストア通知のライフサイクル精査を怠っていた。
- **影響と修正案**:
  探索開始直前のフレームレート低下や不要な再描画オーバーヘッドを招く。
  `restoreBaseSnapshot()` が true を返した場合は `setSolution(undefined)` をスキップするか、または `restoreBaseSnapshot` を `setSolution` のオプション/統合処理にする。

### F5 — P3: 探索中（`solving = true`）における `#share-link` ボタンの無効化漏れ

- **再現**:
  探索中（`solving = true`）、`#scramble`, `#reset`, `#apply-algorithm`, `#save`, `#load`, `#preset-buttons button`, `[data-move]` などの全操作ボタンが `disabled = true` に設定されているが、フッター右側の「共有リンク」（`#share-link`）ボタンだけが `disabled = false` のまま有効化されていた。実測証跡 [`docs/review-evidence/004290a/probe-ui.json`](review-evidence/004290a/probe-ui.json)（`f5ShareLinkEnabledDuringSolve`）を参照。
- **原因**:
  [`web/main.ts`](file:///Users/katoy/github/study-rust/rust-r-cube/3x3-web-2/web/main.ts#L170-L173) の `refresh()` における無効化セレクタ：
  `document.querySelectorAll("[data-move],#scramble,#reset,#apply-algorithm,#edit-colors,#camera-colors,#save,#load,#preset-buttons button")`
  に `#share-link` が含まれていない。
- **先行レビュー（Claude/Codex/Copilot）の見落とし理由**:
  画面上部・中央のタブパネル内のボタンだけを点検し、ワークスペースフッターに配置されている `#share-link` を無効化対象リストから見落としていた。
- **影響と修正案**:
  探索中にクリップボード書き込み等の外部副作用が発生し、UI の無効化ポリシーの一貫性が損なわれる。
  無効化セレクタに `#share-link` を追加する。

| 指摘 | 現行テストが通る範囲 | 見落としていた決定的な境界 |
| :--- | :--- | :--- |
