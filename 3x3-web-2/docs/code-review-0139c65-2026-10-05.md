### 本レビューで明らかにした決定的事実

1. **修正パッチの片手落ちによる WAI-ARIA 仕様違反（H1）**: 前回の指摘（M4）に基づき、`#palette` に `role="radiogroup"` が付与されました。これに伴い `web/camera-results-ui.ts` では正しく子要素に `role="radio"` および `aria-checked` が導入されましたが、**メインのカラーエディタである `web/editor.ts` のパレットボタンには `role="radio"` が付与されず、トグルボタン用の `aria-pressed` が残存** しています。これにより、親が `radiogroup` でありながら必須子ロール（`radio`）を持たない重大な WAI-ARIA 構文違反（`aria-required-children` 欠落）が生じています。
2. **`stop()` における UI 状態同期漏れと再生ボタンの視覚的フリーズ（H2）**: `stop()` 関数は `playing = false` と `playbackRun++` を行いますが、`refresh()` を呼び出しません。この `playbackRun++` により、再生ループ `play()` の `finally` 節にある `if (run === playbackRun)` が `false` と判定されて内部の `refresh()` がスキップされます。そのため、キーボードショートカット（`ArrowLeft`, `ArrowRight`, `Home`, `End`）による手順スキップ時や、`stop()` 直後に `refresh()` を呼ばないコードパスにおいて、**再生が停止しているにもかかわらず再生ボタンのアイコン（`pause`）および `aria-label`（"一時停止"）が画面上に取り残される状態不整合** が発生します。
3. **色解法末尾とセンター解決手順の接合部における冗長回転未相殺（M1）**: `src/lib.rs` の `solve_state_with_algorithm` では、Kociemba、CFOP、Thistlethwaite、Korf で色を揃えた後、残余センター向きを解決するために `supercube::solve_center_orientations` の手順（`center_fixes`）を追加しています。しかし、**色解法の最後の手と `center_fixes` の最初の手の接合部に対して冗長手相殺（`cancel_redundant_moves`）が適用されていません**。例えば色解法の最後が `U` でセンター解決の最初が `U'` であった場合、恒等変換であるにもかかわらず無駄な回転がそのまま解法手順として出力されます。
4. **WASM 公開 API `is_valid` の不自然な契約とセマンティクス乖離（M2）**: WASM 公開 API `is_valid(state)` は `Result<bool, JsValue>` を返しますが、内部実装が `cube::parse_state(state).map(|_| true)` となっているため、**無効な状態を渡した際に `false` を返すことは決してなく、常に例外をスロー** します。一方で `validate(state)` は完成なら `true`、未完成なら `false`、不正なら例外を返す設計となっており、命名と挙動の直感性が逆転しています。
5. **Three.js シーングラフにおける `centerLabels` の `userData.rotation` 欠落（M3）**: `web/scene.ts` では、ピースメッシュや矢印メッシュはすべて `userData.origin` と `userData.rotation` の双方を保持して `finish()` で姿勢を復元していますが、`centerLabels` のみ `rotation` が userData に保存されず、`finish()` 時の位置・姿勢復元が非対称になっています。
6. **ダイアログクローズ時のフォーカス復元（Focus Return）未保証（M4）**: 動的インポートで読み込まれるカラーエディタやカメラエディタを閉じた際、トリガー元ボタン（`#edit-colors`, `#camera-colors`）へのフォーカス復帰が行われず、フォーカスが `document.body` に脱落してキーボード操作が断絶します。

### H1【High・確認済み】`web/editor.ts`: `#palette`（`role="radiogroup"`）配下における `role="radio"` 欠落および `aria-pressed` 不正使用による WAI-ARIA 仕様違反

- **該当箇所**: [`web/editor.ts:101-123`](file:///Users/katoy/github/study-rust/rust-r-cube/3x3-web-2/web/editor.ts#L101-L123), [`web/view.ts:63`](file:///Users/katoy/github/study-rust/rust-r-cube/3x3-web-2/web/view.ts#L63)
- **確証度**: **確認済み**（W3C WAI-ARIA 1.2 仕様および DOM 構造照合）
- **現象**:
  前回のレビュー指摘（M4）に基づき、`web/view.ts` 内のカラーパレットコンテナ `#palette` に `role="radiogroup"` が付与されました。
  ```html
  <!-- web/view.ts:63 -->
  <div id="palette" role="radiogroup" aria-label="入力する色"></div>
  ```
  `web/camera-results-ui.ts` では正しく子要素のボタンに `role="radio"` および `aria-checked` が設定されました（`camera-results-ui.ts:35-36`）。
  しかし、**メインのカラーエディタである `web/editor.ts` の `render()` では、旧来のトグルボタン用実装がそのまま放置されています**：
  ```typescript
  // web/editor.ts:105-111
  const button = document.createElement("button");
  button.className = `color-choice ${count > 9 ? "over" : ""}`;
  button.setAttribute("aria-pressed", String(this.color === color));
  button.setAttribute(
    "aria-label",
    `${NAMES[color]}を選択 残り${9 - count}枚`,
  );
  ```
- **影響**:
  1. **W3C WAI-ARIA 1.2 仕様違反 (`aria-required-children`)**: `role="radiogroup"` を持つ要素の子孫は、必須子ロールとして `role="radio"` を所有しなければなりません。通常の `<button>` のままであるため、支援技術のアクセシビリティツリーで構文違反となります。
  2. **不正な属性の使用 (`aria-pressed`)**: `aria-pressed` は `button` ロール専用の属性であり、`radiogroup` の選択肢には使用できません（ラジオボタンには `aria-checked="true|false"` が必須）。
  3. **スクリーンリーダー操作の破綻**: スクリーンリーダー利用者は「ラジオグループ」と読み上げられるにもかかわらず、子項目をラジオボタンとして操作（矢印キーによる巡回）できず、混乱と操作不能に陥ります。
- **推奨修正案**:
  `web/editor.ts` のボタン生成時に `role="radio"` と `aria-checked` を明示的に設定します。
  ```typescript
  button.type = "button";
  button.setAttribute("role", "radio");
  button.setAttribute("aria-checked", String(this.color === color));
  ```

### H2【High・確認済み】`web/main.ts`: `stop()` 実行時における `refresh()` 欠落および `playbackRun++` による `play()` finally 節スキップに起因する再生ボタン UI 不整合

- **該当箇所**: [`web/main.ts:93-103`](file:///Users/katoy/github/study-rust/rust-r-cube/3x3-web-2/web/main.ts#L93-L103), [`:419-458`](file:///Users/katoy/github/study-rust/rust-r-cube/3x3-web-2/web/main.ts#L419-L458), [`:923`](file:///Users/katoy/github/study-rust/rust-r-cube/3x3-web-2/web/main.ts#L923)
- **確証度**: **確認済み**（非同期実行トレースおよび状態遷移照合）
- **現象**:
  キューブの再生・アニメーションを停止する `stop()` 関数の実装：
  ```typescript
  // web/main.ts:93-103
  function stop() {
    const wasPlaying = playing;
    playing = false;
    playbackRun++;
    motion++;
    scene?.finish();
    inMotion = false;
    if (wasPlaying) {
      persist();
    }
  }
  ```
  自動再生ループ `play()` は以下の構造を持っています：
  ```typescript
  // web/main.ts:432-458
  const run = playbackRun;
  try {
    while (
      playing &&
      run === playbackRun &&
      store.getSolution() === data &&
      store.getStep() < data.moves.length
    ) {
      await seek(store.getStep() + 1);
      ...
    }
  } finally {
    if (run === playbackRun) {
      playing = false;
      persist();
      refresh();
    }
  }
  ```
  外部から `stop()` が呼ばれると、Line 96 で `playbackRun++` がインクリメントされます。
  その結果、再生ループを抜けた後の `finally` 節において、**`if (run === playbackRun)` が `false` となり、内部の `refresh()` がスキップされます**。
  一方、`stop()` 自身も `refresh()` を一切呼び出しません。
  そのため、キーボードショートカット（`ArrowLeft`, `ArrowRight`, `Home`, `End` で `options.onStop()` が呼ばれる場合）や、`stop()` 呼出後に `refresh()` を伴わないイベント処理において、**再生ボタン（`#play`）のアイコン（`pause`）および `aria-label`（"一時停止"）が「再生中」のまま画面上に取り残されます**。
- **影響**:
  ユーザーが再生中に矢印キー等で手順を動かした際、自動再生は停止しているにもかかわらず画面のボタン表示は「一時停止」のままとなり、ボタンを押しても反応が 1 拍ずれるなどの状態表示のデッドロック・不整合が発生します。
- **推奨修正案**:
  `stop()` 内部で `wasPlaying` だった場合に `refresh()` を確実に実行して UI を同期させます。
  ```typescript
  function stop() {
    const wasPlaying = playing;
    playing = false;
    playbackRun++;
    motion++;
    scene?.finish();
    inMotion = false;
    if (wasPlaying) {
      persist();
      refresh();
    }
  }
  ```

### M2【Medium・確認済み】WASM 公開 API `is_valid` の不自然な契約（boolean 戻り値型と例外スローのセマンティクス乖離）

- **該当箇所**: [`src/lib.rs:405-407`](file:///Users/katoy/github/study-rust/rust-r-cube/3x3-web-2/src/lib.rs#L405-L407), [`:440-442`](file:///Users/katoy/github/study-rust/rust-r-cube/3x3-web-2/src/lib.rs#L440-L442)
- **確証度**: **確認済み**（API シグネチャおよび内部エラー伝播の検証）
- **現象**:
  公開 API `is_valid` の定義と実装：
  ```rust
  pub fn is_valid_core(state: &str) -> Result<bool, String> {
      cube::parse_state(state).map(|_| true)
  }

  #[wasm_bindgen]
  pub fn is_valid(state: &str) -> Result<bool, JsValue> {
      is_valid_core(state).map_err(to_js_error)
  }
  ```
  TypeScript / JavaScript の利用者から見ると、`is_valid(state): boolean` という関数は「有効なら `true`、無効なら `false` を返す述語関数」と解釈されます。
  しかし実際には、無効な状態を渡すと `cube::parse_state(state)` が `Err` を返すため、**`false` を返すことは決してなく、必ず例外（JavaScript Error）を throw します**。
  一方で `validate(state)` は「完成状態なら `true`、未完成だが有効なら `false`、不正なら例外」を返します。
- **影響**:
  外部開発者や利用者が `if (wasm.is_valid(state)) { ... }` のように記述した場合、無効な状態で即座に未補足例外が発生してアプリケーションがクラッシュします。
- **推奨修正案**:
  `is_valid` は例外をスローせず、純粋なブーリアン述語（`cube::parse_state(state).is_ok()`）として `bool`（または `Result` でなく直接 `bool`）を返す仕様に是正するか、例外をスローするバリデーション関数としての仕様を明文化します。

### M3【Medium・確認済み】`web/scene.ts`: `centerLabels` の `userData.rotation` 欠落と `finish()` 時の姿勢復元の非対称性

- **該当箇所**: [`web/scene.ts:184`](file:///Users/katoy/github/study-rust/rust-r-cube/3x3-web-2/web/scene.ts#L184), [`:553-558`](file:///Users/katoy/github/study-rust/rust-r-cube/3x3-web-2/web/scene.ts#L553-L558)

  `centerLabels` にも `userData.rotation` を保持させ、`finish()` 時に `label.quaternion.copy(label.userData.rotation)` を行うことで対称性を担保します。

- **該当箇所**: `web/main.ts:1009-1014`, `web/url-params.ts:13`
- **内容**: `parseUrlParams` では `solver` のエイリアスとして `algorithm` を受け付けるが、パラメータ適用後の `searchParams.delete` で `algorithm` が削除されないため、URL バーにクエリが残存する。

### L3【Low】`web/url-params.ts`: 共有リンク（`buildShareUrl`）に解法アルゴリズム設定（`solver`）が伝搬されない
- **該当箇所**: `web/main.ts:846-859`, `web/url-params.ts:52-66`
- **内容**: `parseUrlParams` は `solver` パラメータの復元に対応しているが、共有リンクボタン（`#share-link`）で生成される URL には `solver` が含まれない。ユーザーが CFOP や Korf を選択して共有リンクを作成した場合でも、相手側には反映されない。

### L4【Low】`public/sw.js`: キャッシュキーソートにおける文字列辞書順ソートの限界
- **該当箇所**: `public/sw.js:92`
- **内容**: `const sortedOldKeys = [...oldKeys].sort();` において、将来キャッシュバージョンが `v9` から `v10` に上がった場合、辞書順では `"v10" < "v9"` となり、最新の `v10` ではなく古い `v9` が pop される。自然順ソート（`localeCompare(..., undefined, { numeric: true })`）の採用を推奨。

### L5【Low】`web/main.ts`: `openModal` 動的インポート中の競合ガードの強化
- **該当箇所**: `web/main.ts:594-618`
- **内容**: `openModal` はリビジョン番号と状態チェックを行っているが、インポート処理中に探索が完了して解法プレビューに入った場合のエラーハンドリングをより明瞭にする余地がある。

### L6【Low】`web/centers.ts`: `centersFromInput` のエラーハンドリングと不正値トレース
- **該当箇所**: `web/centers.ts:22-39`
- **内容**: 不正なセンター配列が渡された際のエラーメッセージで、どの面が不正な範囲であったかの詳細を含めることでデバッグ性を向上可能。
