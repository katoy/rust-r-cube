## 指摘（優先順）

### F1 — P2: 解法プレビュー中の手動操作で、プレビュー開始前の局面を失う

**再現:** 実画面で `R` を回し、解法を求めて「最後の手順へ」で完成状態に進み、`U` を手動回転して Undo した。完成状態に戻った時点で Undo が無効になり、最初の `R` 局面へ戻れない。[操作スクリプト](review-evidence/125f8c8/probe-preview-mutation.mjs)と[全状態の記録](review-evidence/125f8c8/probe-preview-mutation.json)を保存した。

**原因:** [`updateAfterSeek`](../web/cube-store.ts#L186) は現在局面だけを変える。直前の修正は [`setSolution`](../web/cube-store.ts#L166) に履歴確定を追加したが、手動回転は [`applyAlgorithmResult`](../web/cube-store.ts#L198) へ直接進み、プレビュー中の完成局面を履歴に積んで `baseSnapshot` を捨てる。`replace` も同じ構造。画面側の[手動回転経路](../web/main.ts#L431)は `setSolution(undefined)` を呼ばない。

**影響と修正案:** 解法再生の後に手動回転・リセット・ファイル/プリセット読込をすると、解法前の状態を Undo で復元できない場合がある。プレビューから通常操作へ移る全経路で、`baseSnapshot → プレビュー局面 → 新局面` の履歴方針を一箇所で確定する。`R → 解法最終手 → U → Undo×2` と `R → 解法最終手 → リセット → Undo` を画面テストに加える。

### F2 — P3: 同じアプリの別名URLで効果音設定が分離する

**再現:** `/` で効果音をオフにするとボタンは `aria-pressed=false`、保存キーは `cube_studio_sound_enabled`。同じオリジンの `/index.html` へ移動すると効果音がオンに戻った。[操作スクリプト](review-evidence/125f8c8/probe-sound-scope.mjs)と[結果](review-evidence/125f8c8/probe-sound-scope.json)を参照。

**原因:** [`sound.ts`](../web/sound.ts#L1) は `window.location.pathname` をそのままキーに含める。キューブ状態の [`getScopedStorageKey`](../web/main.ts#L36) は `/` と `/index.html` を同一視しており、保存スコープの設計と食い違う。サブディレクトリの `/nested/cube/` と `/nested/cube/index.html` でも同じ分離が起こる。

**影響と修正案:** 利用者のミュート選択がページの別名URLで効かない。全設定で同じパス正規化関数を使用し、ルートとサブディレクトリの別名URLをまたぐ保存・復元をテストする。

### F3 — P3: 遅れて読み込まれたカメラ画像が利用者のビュー選択を戻す

**再現:** カメラ画面で画像Aのデコードを保留し、その間に利用者がビューBへ切り替えた。Aの読み込み完了後、表示はAへ戻った。[操作スクリプト](review-evidence/125f8c8/probe-camera-view-race.mjs)と[結果](review-evidence/125f8c8/probe-camera-view-race.json)を参照。画像Aの保存先は正しく、問題は現在の表示選択に限られる。

**原因:** [`processFile`](../web/camera.ts#L361) の世代番号は同一ビューの古いデコードを排除するが、完了時に [`this.currentView = view`](../web/camera.ts#L458) を無条件に実行する。縮小画像の完了経路も[同様](../web/camera.ts#L431)。利用者による [`switchView`](../web/camera.ts#L344) は読み込み世代を変更しない。

**影響と修正案:** 大きな画像や連続したA/B選択で、利用者が今見ている面と操作対象が突然変わり、誤った面を読み取りやすい。画像は指定ビューへ保存しつつ、表示切替はその読み込み要求が最後の明示的なビュー選択より新しい場合だけ行う。A/B の逆順完了テストを加える。

### F4 — P3: 公開ファイルの削除後も古い `dist` を最新と判定する

**再現:** 一時アセットを含むビルドは20ファイルをプリキャッシュ。元ファイルを削除後に `node scripts/launch-offline.js --headless` を実行すると、再ビルドせず「既存の最新ビルド」を使用し、古い20ファイルでオフライン起動成功を報告した。[再現記録](review-evidence/125f8c8/operational-probes.md)を参照。作業後の再ビルドで19ファイルに戻した。

**原因:** [`ensureBuild`](../scripts/launch-offline.js#L40) は現存するソースと一部設定の最終 `mtime` を `dist/index.html`・`dist/sw.js` と比較する。削除前に存在したファイルの情報を保持しないため、削除を検出できない。直前の修正で設定ファイルの変更は対象になったが、この欠落は残る。

**影響と修正案:** オフライン検証が既にソースにないファイルを使って成功し、「現在のコードで動く」という結論が偽陽性になる。検証モードは毎回ビルドするか、入力ファイル一覧と内容ハッシュを記録して現在の一覧と比較する。
