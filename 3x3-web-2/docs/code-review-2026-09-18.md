## 指摘詳細

### R01 — カメラダイアログのEsc終了でストリームを停止しない

**根拠:** [camera.ts:176](../web/camera.ts#L176)、[camera.ts:808–835](../web/camera.ts#L808)。停止処理を呼ぶ `close()` は閉じるボタンと適用ボタンから呼ばれるが、`dialog` 自体の `cancel` / `close` イベントには接続されていない。

**再現・影響:** ライブカメラを開始し、映像取得後にEscを押す。ダイアログは閉じるが、取得しておいた映像トラックの `readyState` は `live`、`video.srcObject` も残ることを確認した。見えない状態で映像取得と描画ループが継続する。外部送信を確認したという指摘ではない。

**修正方針:** ダイアログのすべての終了経路で、トラック・RAF・参照を冪等に解放する。また、`getUserMedia()` 待機中に閉じた場合も、後から取得したストリームを世代番号等で無効化して停止する。

**追加テスト:** ボタン、Esc、取得待ち中の終了について、全トラックが `ended` になりRAFが継続しないことを検証する。既存の `camera-live.spec.ts` はボタンの存在とダイアログ終了を調べるだけで、映像取得を開始していない。

### R02 — 自分のもの以外のCache Storageまで削除する

**根拠:** [sw.js:21–30](../public/sw.js#L21)。`caches.keys()` の結果から `cube-studio-v1` 以外をすべて削除する。

**再現・影響:** 同一オリジンに `another-app-v1` を作成してからアプリのService Workerを有効化すると、キャッシュ一覧が `["cube-studio-v1"]` だけになる。別パスのアプリ用キャッシュも対象になるため、同一GitHub Pagesオリジン等で併設したアプリのオフライン資産を消してしまう。Service Workerの登録scopeでは、この削除対象は限定されない。

**修正方針:** アプリと配置パスを識別する専用プレフィックスを定義し、そのプレフィックスに一致する旧版だけを削除する。

**追加テスト:** 同一オリジンに他アプリのキャッシュを作成した状態で、初回activateとバージョン更新を行っても残ることを確認する。

### R03 — クリーンなCIでカメラテストのfixtureが欠ける

**根拠:** [CI:65–69](../../.github/workflows/3x3-web-2.yml#L65)、[package.json:13–16](../package.json#L13)、[.gitignore:11](../.gitignore#L11)、[test-utils.ts:48–50](../tests/test-utils.ts#L48)。`test-images/` は追跡されておらず、CIは生成処理を実行せずに `npx playwright test` を呼ぶ。生成を含む `test:camera` はCIから呼ばれていない。

**再現・影響:** 依存を既存環境から参照する一時ディレクトリに、カメラテストとヘルパーのみを配置して先頭のマニフェスト確認を実行した。`test-images/manifest.json` の読み取りが `ENOENT` で失敗した。ローカルに画像が既にある場合は成功するため、今回の通常テスト成功だけではCIの再現性を保証できない。

**修正方針:** CIのテスト実行前、またはPlaywrightの共通セットアップで `npm run generate-test-images` を実行する。専用テストコマンド経由に統一する場合は、CIの直接呼び出しも変更する。

**追加テスト:** 生成済み画像を持ち込まないクリーンチェックアウトで、依存導入・ビルド・画像生成・全テストが成立することを確認する。

### R04 — プリセット取得URLがオリジン直下に固定されている

**根拠:** [main.ts:790–799](../web/main.ts#L790)。`fetch('/cubes/...')` はViteの相対baseや公開先のサブディレクトリを反映しない。デプロイ先は [deploy-pages.yml](../../.github/workflows/deploy-pages.yml) の `3x3-v2/` 配下。

**再現・影響:** 本番ビルドを `/nested/cube/` で開き、「簡単（5手）」を選ぶと、要求先は `/cubes/easy-5-moves.json` になり404となった。`/nested/cube/cubes/...` が正しい配置先。すべてのプリセットが同じ実装を通る。

**修正方針:** 配置baseから解決したURL、またはこのアプリのページ構造に合う相対URLを使用する。

**追加テスト:** 既存のサブディレクトリテストはスクランブルと探索のみを検証しているため、同じ本番previewで全プリセットの読み込みも検証する。

### R05 — 3D矢印とセンター文字の回転符号が逆

**根拠:** [scene.ts:353](../web/scene.ts#L353)、[scene.ts:383–389](../web/scene.ts#L383)、[scene.ts:438–439](../web/scene.ts#L438)。モデルの角度は時計回りを正とするが、外向き法線への `applyAxisAngle(n, angle)` に同じ符号を渡している。回転アニメーションでは逆に `-Math.PI / 2` を使っている。

**再現・影響:** 完成状態から `U` を1回実行した。センターの保存値は1 quarter turn、2D展開図は `→`、メタデータは `+π/2`。一方、Uセンター矢印メッシュのローカル上方向をquaternionで変換すると約 `[-1, 0, 0]` で、期待する時計回りの `[1, 0, 0]` と逆だった。3D表示を見てセンター方向を読み取ると90°と270°を取り違える。

**修正方針:** 時計回り角度から3D軸角への変換を一か所に定義し、矢印とセンター文字に同じ正しい符号を使用する。

**追加テスト:** メタデータの `rotAngle` だけではなく、6面の矢印先端方向・quaternionを独立した幾何期待値と比較する。既存の `app.spec.ts:605–794` は主にメタデータを検証しており、この表示不整合を検出できない。

### R06 — 同じスクランブル共有URLが再読み込みごとに変化する

**根拠:** [main.ts:709–741](../web/main.ts#L709)。保存局面を復元した後、`?alg=` を現在局面へ適用する `applyAlgorithm()` に渡している。

**再現・影響:** 新しいブラウザコンテキストで `/?alg=R` を開くと `R` の局面になる。同じURLを再読み込みすると、保存済みの `R` にもう一度 `R` が適用され、`R2` と一致した。共有先の保存状態によっても結果が変わり、同じリンクが同じ局面を表さない。

**修正方針:** URL由来のスクランブルは完成状態とゼロのセンター回転から構築する。手動入力欄の「現在の状態に適用」とは初期状態の扱いを分ける。

**追加テスト:** 別の局面が保存されている場合、および同じURLを複数回再読み込みした場合に、同一スナップショットになることを検証する。

### R07 — 共有リンクでスーパーキューブの状態を再現できない

**根拠:** [main.ts:571–574](../web/main.ts#L571)、[main.ts:730–734](../web/main.ts#L730)。出力するのは54文字の配色だけで、読み込み時には `automaticCenters()` が別のセンター方向を生成する。JSON保存では `centerTurns` を含めているが、URL共有では含めていない。

**再現・影響:** 完成配色のUセンターを180°にした合法状態 `[2,0,0,0,0,0]` から共有リンクを作成して開いたところ、`[0,0,0,0,0,0]` に変化した。同じ配色でも必要なセンター補正が異なるため、共有元と異なる問題・解法になる。

**修正方針:** センター方向もURLへシリアライズし、既存の `centersFromInput()` 相当の検証を通して復元する。旧形式の配色のみのURLは互換動作を明示する。

**追加テスト:** 色完成・センター未完成の状態について、共有前後の `getSnapshot()` 全体が一致することを検証する。

### R08 — 音声設定の読み取り例外で画面全体が起動しない

**根拠:** [sound.ts:7–10](../web/sound.ts#L7)、[sound.ts:32–35](../web/sound.ts#L32)。モジュール評価時に生成する `SoundManager` のコンストラクタが、例外処理なしで `localStorage.getItem()` を呼ぶ。

**再現・影響:** 初期化前に `Storage.prototype.getItem` が `SecurityError` を投げるよう注入して起動した。`#app` の子要素数は0で、未処理の `SecurityError` が発生した。`main.ts` にある保存失敗時のフォールバックへ進む前に停止する。音声の切り替え時の `setItem()` にも同様の未処理例外経路がある。

**修正方針:** 音声設定の読み書きにも例外処理を設け、保存領域が使えなくてもメモリ上の設定とアプリ起動を維持する。

**追加テスト:** ストレージ読み取り拒否と書き込み拒否を別々に模擬し、キューブ操作と音声ボタンが利用できることを確認する。

### R09 — 復元した再生速度と動作軽減設定が次回起動で消える

**根拠:** [main.ts:216–225](../web/main.ts#L216)、[main.ts:717–721](../web/main.ts#L717)。復元中の `store.replace()` が通知を出して `persist()` を呼ぶ。この時点では速度と動作軽減設定がUIへ復元されておらず、初期値で保存済み設定を上書きする。

**再現・影響:** 解法を表示して速度を2×、動きを減らすを有効に設定する。1回目の再読み込みでは画面が `250/true` に復元される一方、保存領域は既に `500/false` になる。そのまま再度読み込むと画面も `500/false` へ戻った。

**修正方針:** 復元処理全体が完了するまで永続化を抑止するか、すべての設定を反映してからストアへ通知する。

**追加テスト:** 保存値とUIの両方を、操作を挟まない2回連続の再読み込みで検証する。

### R10 — 初回訪問の必須JS/CSSがオフライン用に保存されない

**根拠:** [sw.js:3–9](../public/sw.js#L3)、[pwa.ts:10–13](../web/pwa.ts#L10)。インストール時のプリキャッシュはHTML・manifest・アイコンのみ。初回ページは `load` 後に登録されるService Workerより先に主要JS/CSSを取得している。

**再現・影響:** 新規コンテキストで本番previewの `/nested/cube/` を開き、READYとService Workerによる制御開始まで待つ。そのままオフラインにして再読み込みすると本文が空になり、`#engine-status` も存在しなかった。キャッシュにはHTML・アイコン等とWorker/WASMがあったが、main・Three.js・CSSがなかった。READMEの「一度アクセスすれば完全オフラインで利用可能」を満たしていない。

**修正方針:** ビルド成果物のハッシュ付きJS/CSS、Worker/WASMを含むプリキャッシュ一覧を生成する。「完全オフライン」に含めるなら、遅延ロードするエディタ・カメラとプリセットJSONも対象とする。

**追加テスト:** [pwa.spec.ts:73–75](../tests/pwa.spec.ts#L73) のような事前のオンライン再読み込みを挟まず、本番ビルドで初回訪問→オフライン再起動を検証する。未使用だったエディタ・カメラをオフラインで初めて開く場合も確認する。

### R11 — 未認識センターを補正できず、認識済み色を捨てて入力し直すことになる

**根拠:** [camera.ts:455–475](../web/camera.ts#L455)、[camera-results-ui.ts:90–93](../web/camera-results-ui.ts#L90)、[editor.ts:62–69](../web/editor.ts#L62)。センターが `?` の場合は割当先だけをフォールバックし、ステッカー文字列自体は `?` のまま保存する。センターセルは両方のエディタで編集不可。

**再現・影響:** 黒いテスト画像をA/Bとして読み取り、6面を色入力へ反映した。カメラ結果の6センターすべてが `color: "?", disabled: true`、カラーエディタ側も6センターが `?` のままだった。実写でセンターだけ判別不能になった場合も同じ経路を通る。周辺ステッカーを補正してもセンターを直せず、適用に失敗する。「センター以外を未入力にする」で固定センターへ戻せるが、周辺48セルも消してしまう。

**修正方針:** 期待する面のセンター色を保持したうえで未認識を警告するか、認識済みの周辺色を維持したままセンター不整合を解消できる経路を用意する。

**追加テスト:** 周辺8セルは正しく、センターだけが未認識の面を用意し、周辺データを失わずに有効な局面へ確定できることを確認する。既存のpartial画像テストは `?` が引き継がれることまでしか検証していない。

### R12 — 4タブ構成なのにキーボード巡回が3タブ固定

**根拠:** [main.ts:558–565](../web/main.ts#L558)。タブ数が4なのに `% 3` と左方向の `+2` を使用する。

**再現・影響:** スクランブルタブにフォーカスして右矢印を4回押すと、`presets → colors → scramble → presets` と移動した。「手順を入力」タブに到達しない。このタブは非選択時 `tabindex=-1` のため、通常のTab移動でも直接フォーカスできない。

**修正方針:** `tabs.length` と方向に応じた `+1/-1` で巡回先を求める。

**追加テスト:** 4タブすべてへの左右矢印移動と端の折り返しを実操作で検証する。静的なアクセシビリティ監査の成功だけでは検出できない。

### R13 — カバレッジ100%の判定が未実行コードを含んでいる

**根拠:** [coverage.spec.ts:430–450](../tests/coverage.spec.ts#L430)、[coverage.spec.ts:391–402](../tests/coverage.spec.ts#L391)。V8の関数別範囲を平坦化し、実行回数が正の親範囲にある行をすべて「実行済み」にする。`count: 0` の子範囲を単に読み飛ばしても、先に親範囲から加えた行は除去されない。

**再現・影響:** PlaywrightのJS coverageで次のコードを読み込み、関数は呼び出さず、レポートと同じ集計処理を適用した。

```javascript
window.reviewUsed = 1;
function reviewNeverCalled() {
  window.reviewNeverRan = 42;
  window.reviewNeverRanAgain = 43;
}
```

V8はスクリプト全体を `count: 1`、`reviewNeverCalled` を `count: 0` と返した。`window.reviewNeverRan` は `undefined` のままだが、集計は **100%** と判定した。したがって現行テストの100%表示を、各モジュールの全行・全分岐を検証した証拠として扱えない。

**修正方針:** 範囲の包含関係と未実行の子範囲を処理できる既存のV8 coverage変換処理を使うか、正しく区間を正規化してから集計する。変換後のJSを対象にしている点も明示し、TypeScriptの行カバレッジを主張するならソースマップを反映する。

**追加テスト:** 未呼び出しの複数行関数と未通過分岐を含むfixtureで、該当行が未実行になることを確認してから閾値を設定する。
