### Finding 1: `classifyColor` の Zero-allocation 化 (`web/image-sampler.ts`)

#### 背景と課題
`web/image-sampler.ts` の `classifyColor` において、`rgbToHsv` を呼び出すたびに `{ h, s, v }` という JavaScript オブジェクトがヒープ上に確保されていました。
サンプリング半径 $r=5$ では 1 セルあたり 121 回、1 面あたり 1,089 回、Two-View 6 面で 6,534 回ものオブジェクトアロケーションが集中し、V8 ガベージコレクタの Minor GC（Scavenge）を誘発していました。

#### 修正内容
`classifyColor` の内部で HSV 変換をローカルプリミティブ変数（`rf`, `gf`, `bf`, `max`, `min`, `d`, `s`, `v`, `h`）として直接インライン計算するように変更しました。これにより、ピクセルサンプリング時のヒープアロケーションが完全にゼロ（Zero-allocation）になりました。なお、外部エクスポート関数 `rgbToHsv` は後方互換性および単体テストのために維持しています。

```typescript
// 修正後 (web/image-sampler.ts)
export function classifyColor(r: number, g: number, b: number): string {
  const rf = r / 255;
  const gf = g / 255;
  const bf = b / 255;
  const max = Math.max(rf, gf, bf);
  const min = Math.min(rf, gf, bf);
  const d = max - min;
  const s = max === 0 ? 0 : d / max;
  const v = max;

  // 1. 極端に暗いピクセル（黒プラスチック目地、完全な暗闇など）
  if (v < 0.18 || (s < 0.25 && v < 0.45)) {
    return "?";
  }

  // 2. 白（低彩度かつ十分な明度）
  if (s < 0.28 && v >= 0.45) {
    return "U";
  }

  let h = 0;
  if (max !== min) {
    if (max === rf) {
      h = (gf - bf) / d + (gf < bf ? 6 : 0);
    } else if (max === gf) {
      h = (bf - rf) / d + 2;
    } else {
      h = (rf - gf) / d + 4;
    }
    h *= 60;
  }

  // 3. 有彩色（色相 H: 0〜360 による判定）
  if (h >= 75 && h <= 170) return "F"; // 緑
  if (h > 170 && h <= 265) return "B"; // 青
  if (h >= 40 && h < 75) return "D";   // 黄
  if (h >= 18 && h < 40) return "L";   // 橙
  if (h < 18 || h >= 340) return "R";  // 赤

  return "?";
}
```

### Finding 2: CFOP 探索への `redundant` 枝刈り導入 (`src/cfop.rs`)

#### 背景と課題
他の 3 つのソルバー（Kociemba, Korf, Thistlethwaite）では対向面の可換性（$[U, D] = 0$, $[R, L] = 0$, $[F, B] = 0$）を考慮した `redundant(face, last)` 枝刈りが適用されていましたが、`src/cfop.rs` のクロス探索および第1層コーナー探索では `if face == last_face` しか除外されておらず、対向面の可換枝（$U D$ と $D U$ 等）が重複して探索されていました。

#### 修正内容
`src/cfop.rs` に `#[inline] fn redundant(face: usize, last: usize) -> bool` を導入し、`search_cross_edge` および `search_corner` の探索ループに適用しました。また、ユニットテスト `test_cfop_redundant` を追加しました。

```rust
// 修正後 (src/cfop.rs)
#[inline]
fn redundant(face: usize, last: usize) -> bool {
    face == last || ((3..6).contains(&last) && face + 3 == last)
}

fn search_cross_edge(...) -> Result<bool, String> {
    // ...
    for face in 0..6 {
        if redundant(face, last_face) {
            continue;
        }
        // ...
    }
}

fn search_corner(...) -> Result<bool, String> {
    // ...
    for face in 0..6 {
        if face == 3 || redundant(face, last_face) {
            continue;
        }
        // ...
    }
}
```

### Finding 4: `CubeScene.turn()` のレイヤー再利用化（GCゼロ化） (`web/scene.ts`)

#### 背景と課題
1 回の回転操作ごとに `const layer = new THREE.Group(); this.root.add(layer);` が呼び出され、回転完了後に `this.root.remove(active.layer);` されていました。Vector3 のキャッシュ化に続き、グループオブジェクトの生成・破棄も排除することで、シーングラフのノード管理を最適化する余地がありました。

#### 修正内容
`CubeScene` の初期化時に単一の回転用グループ `private turnLayer = new THREE.Group();` を `this.root` にあらかじめ追加しておき、`turn()` では `this.turnLayer` を使い回す設計に変更しました。回転終了時（`finish()`）にはクォータニオンを単位元にリセットし、子要素を `root` や `arrowGroup` に復帰させます。

```typescript
// 修正後 (web/scene.ts)
// クラス定義
private turnLayer = new THREE.Group(); // 回転アニメーション用レイヤー（再利用でGCゼロ化）

// コンストラクタ
this.root.add(this.turnLayer);

// turn()
async turn(move: string, state: string, duration: number) {
  // ...
  const axis = normal[FACES.indexOf(move[0])];
  const layer = this.turnLayer;
  layer.quaternion.identity();
  this.pieces
    .filter((mesh) => mesh.position.dot(axis) > 0.5)
    .forEach((mesh) => layer.attach(mesh));
  // ...
}

// finish()
finish() {
  // ...
  this.turnLayer.quaternion.identity();
  this.turnLayer.clear();
  active.finish();
}
```
