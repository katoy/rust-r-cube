  - [`web/main.ts`](file:///Users/katoy/github/study-rust/rust-r-cube/3x3-web-2/web/main.ts): `catch (err)` 内で、`const msg = err instanceof Error ? err.message : String(err);` および `const isTimeout = /timeout|タイムアウト/i.test(msg);` によりタイムアウト例外を厳密に判定。タイムアウト時のみ extended ボタンを表示し、タイムアウト以外のエラーでは extended ボタンを非表示にした上で正しいエラーメッセージを通知するよう改修。

## 根本原因の構造的解消：AppState（Idle | Solving | Previewing）有限状態機械の導入

### 背景と目的
個別のイベントハンドラに `if (solving)` やフラグ判定を追加する対症療法（モグラ叩き）では、非同期 I/O や UI 操作の組み合わせ増加に伴い、新たな競合レースや仕様の揺れが発生しやすい構造的要因がありました。
この根本原因を断ち切るため、[`web/app-state.ts`](file:///Users/katoy/github/study-rust/rust-r-cube/3x3-web-2/web/app-state.ts) を新設し、明確な **State パターン（GoF）および有限状態機械（FSM）** を導入しました。

### 導入された状態モデル
- **`IdleState`（アイドル・通常状態）**:
  - キューブの編集（手動回転、スクランブル、リセット、手順適用、プリセット読込、ファイル読込など）が可能。
  - 探索（`solve`）の開始、Undo/Redo、保存、共有が可能。
- **`SolvingState`（探索中状態）**:
  - 探索 Worker が稼働中。
  - キューブの盤面変更、新たな探索開始、Undo/Redo、外部読み込みを**型およびステートマシンレベルで一括遮断**。
  - 許可されるのは探索キャンセル（`cancelSolving`）のみ。
- **`PreviewingState`（解法プレビュー中状態）**:
  - 解法のステップ閲覧、自動再生（`play`）、シーク（`seek`）、解法コピーが可能。
  - 解法パネルのクローズ（`closeSolution`）により通常状態（`Idle`）へ遷移。
  - プレビュー中に手動回転などの盤面変更操作が行われた場合、`beforeModifyCube()` フックにより自動的にプレビューを確定・解除して `Idle` 状態へ安全に復帰。

### 成果
- [`tests/app-state.spec.ts`](file:///Users/katoy/github/study-rust/rust-r-cube/3x3-web-2/tests/app-state.spec.ts): 状態遷移の不変条件と不正操作の遮断を検証する単体テスト 8 件を新設し、すべて合格。
- `web/main.ts` 内の散在していた `if (solving)` 条件分岐が一元化され、不正な状態遷移の混入を構造的に防止。
