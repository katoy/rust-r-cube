## 2. 深層改善課題（Findings 1〜6）の修正詳細

### ✅ Finding 1: [`src/cfop.rs`](../src/cfop.rs) — OLL/PLL 定石マクロパースのキャッシュ化（Zero-allocation）

- **問題点**:
  `solve_oll`（57パターン）および `solve_pll`（21パターン）の実行において、毎回 `moves("...")` を呼び出して文字列表記を走査・解析し、`Vec<usize>` をヒープ確保していた。CFOP 解法ソルバーが高頻度で呼び出された際に不要なメモリアロケーションと CPU オーバーヘッドが生じていた。
- **対応内容**:
  `std::sync::OnceLock` を活用し、OLL および PLL の定石マクロ手順（合計 78 パターン）を初回アクセス時にパースして静的配列 `&'static [Vec<usize>]` としてキャッシュ。2回目以降の呼び出しではヒープ確保を一切行わない完全な Zero-allocation 化を達成。

```rust
// src/cfop.rs
fn get_oll_moves() -> &'static [Vec<usize>] {
    static OLL_CACHE: OnceLock<Vec<Vec<usize>>> = OnceLock::new();
    OLL_CACHE.get_or_init(|| {
        OLL_ALGS.iter().map(|&alg| moves(alg)).collect()
    })
}

fn get_pll_moves() -> &'static [Vec<usize>] {
    static PLL_CACHE: OnceLock<Vec<Vec<usize>>> = OnceLock::new();
    PLL_CACHE.get_or_init(|| {
        PLL_ALGS.iter().map(|&alg| moves(alg)).collect()
    })
}
```

### ✅ Finding 2: [`src/cube.rs`](../src/cube.rs) — WCA 規則準拠のスクランブル対向面枝刈り

- **問題点**:
  WCA（World Cube Association）公式規則 Article 4 では、スクランブル生成時に対向面の連続回転による手数の実質的相殺（例: `R L R'` 等）を禁止している。従来の `scramble(seed)` では直前の 1 手のみを比較していたため、可換な対向面を挟んだ重複手番が生成される可能性があった。
- **対応内容**:
  対向面のペア関係を判定する `is_opposite_face(face1, face2)` ヘルパー関数を実装。直前の手（`last_face`）に加え、2手前の手（`second_last_face`）が対向面である場合、同軸の回転を枝刈りする WCA 準拠のフィルタリングロジックを導入。

```rust
// src/cube.rs
#[inline]
fn is_opposite_face(f1: usize, f2: usize) -> bool {
    // 0:U, 1:D | 2:L, 3:R | 4:F, 5:B
    (f1 / 2) == (f2 / 2)
}

// スクランブル生成ループ
if face == last_face {
    continue;
}
if let Some(prev2) = second_last_face {
    if is_opposite_face(face, last_face) && face == prev2 {
        continue;
    }
}
```

### ✅ Finding 4: [`web/main.ts`](../web/main.ts) — 手順タイムライン更新の $O(1)$ 差分更新化

- **問題点**:
  解法手順再生時に `refresh()` が呼び出されるたび、手順リスト内の全ボタン（最大 100 手以上）に対して `querySelectorAll(".step-btn")` で DOM を走査し、`classList.toggle` を実行していたため、再生アニメーション中に $O(N)$ の DOM レイアウト計算コストが発生していた。
- **対応内容**:
  直前にアクティブだったボタンのステップ番号（`previousActiveStep`）を記憶し、前回のボタンから `active` / `passed` クラスを解除し、新しいボタンのみにクラスを付与する $O(1)$ の差分更新アルゴリズムへ移行。長手数の手順再生時でも 60fps を安定維持。

```typescript
// web/main.ts
if (previousActiveStep !== undefined && previousActiveStep !== step) {
  const prevBtn = list.querySelector(`[data-step="${previousActiveStep}"]`);
  if (prevBtn) prevBtn.classList.remove("active", "passed");
}
const currentButton = list.querySelector(`[data-step="${step}"]`);
if (currentButton) {
  currentButton.classList.add("active");
  currentButton.scrollIntoView({ block: "nearest", inline: "nearest" });
}
previousActiveStep = step;
```

### ✅ Finding 5: [`web/url-params.ts`](../web/url-params.ts) — センター回転パラメータの厳格バリデーション

- **問題点**:
  URL クエリパラメータ `?centers=...` をパースする際、カンマ区切り文字列の長さのみを判定しており、各要素が不正な文字列や範囲外の値（例: 負数や 4 以上の数値）であってもそのままモデルに渡される脆弱性があった。
- **対応内容**:
  各要素が有限な整数であり、かつ 0〜3 の正規化された四元数回転角（$0^\circ, 90^\circ, 180^\circ, 270^\circ$）の範囲内にあることを厳格に検証する述語ロジックを追加。無効値が含まれる場合は安全にデフォルト値 `[0, 0, 0, 0, 0, 0]` にフォールバック。

```typescript
// web/url-params.ts
const parsedCenters = rawCenters.split(",").map(Number);
if (
  parsedCenters.length === 6 &&
  parsedCenters.every((c) => Number.isInteger(c) && c >= 0 && c <= 3)
) {
  centers = parsedCenters;
}
```

```typescript
timeline.setAttribute("aria-valuenow", String(step));
```
