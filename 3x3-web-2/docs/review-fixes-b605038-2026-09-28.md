## 指摘事項別の対応詳細

### F1 (P2): 解法プレビューシーク後（または再生完了後）の再探索により、元のスクランブル局面ではなくプレビュー途中の局面が探索対象になり、元の局面情報が失われる

- **問題:** 解法プレビューで途中ステップまでシークした後に別のアルゴリズムを選択して「解法を探す」（`#solve`）をクリックすると、探索 Worker に渡される局面が元のスクランブル局面ではなくプレビュー途中の局面（5手目など）になり、元のスクランブルおよびその解法が失われていた。
- **原因:** [`web/main.ts`](../web/main.ts) の `solve()` 冒頭で `store.setSolution(undefined)` を呼んでいたが、[`CubeStore.setSolution(undefined)`](../web/cube-store.ts) は `this.baseSnapshot` をクリアするだけであり、`this.state` はシーク途中の局面のまま放置されていた。
- **修正内容:**
  - [`web/cube-store.ts`](../web/cube-store.ts): `restoreBaseSnapshot(): boolean` メソッドを追加。プレビュー中であれば元のスクランブル局面（`baseSnapshot.state`）およびセンター向き（`baseSnapshot.centerTurns`）にロールバックして `this.baseSnapshot` をクリアする。
  - [`web/main.ts`](../web/main.ts): `solve()` の冒頭で直ちに `store.restoreBaseSnapshot()` を呼び出し、再探索時に必ず元のスクランブル局面にロールバックしてから探索 Worker を起動するように是正。
- **検証結果:**
  - 新規回帰テスト [`tests/code-review-b605038-regression.spec.ts`](../tests/code-review-b605038-regression.spec.ts) にて、5手目へシークした後に CFOP で再探索した際、解法の step 0 が元のスクランブル局面と一致し、プレビュー途中の局面にすり替わらないことを確認。

### F2 (P2): 探索中（`solving = true`）の Undo / Redo 操作により探索が中断されず、UI拘束とバックグラウンドでのゴースト探索が継続する

- **問題:** 時間のかかる探索が走っている最中に画面の「元に戻す（Undo）」ボタンを押すと、3D 盤面は過去の局面に戻るが、探索 Worker はキャンセルされずに古い局面の探索を継続し、UI は「探索中」タイマーで最大30秒拘束されていた。
- **原因:** [`web/main.ts`](../web/main.ts) の `refresh()` において `#undo` / `#redo` の `disabled` 判定に `solving` が含まれておらず、また `undo.onclick` / `redo.onclick` で `cancelSearch()` が呼ばれていなかった。
- **修正内容:**
  - [`web/main.ts`](../web/main.ts): `refresh()` において、`#undo` と `#redo` ボタンの `disabled` に `|| solving` を追加し、探索中の不用意な履歴操作を物理的に無効化。
  - [`web/main.ts`](../web/main.ts): `undo.onclick` および `redo.onclick` の冒頭で直ちに `stop()` と `cancelSearch()` を呼び出し、実行中の探索 Worker を即時停止・リセット。
- **検証結果:**
  - 新規回帰テストにて、探索中に `#undo` / `#redo` ボタンが `disabled` になること、および万が一発火した場合も即座に `cancelSearch()` が呼ばれて探索 Worker が中断されることを確認。

### F3 (P2): 探索中に「色を入力」「カメラで読み取り」ダイアログを起動した際の非同期レース

- **問題:** 探索が走っている最中に「色を入力」や「カメラで読み取り」モーダルを開くと、背後で探索が継続し、モーダル入力中に背後で解法が適用・上書きされる競合が発生していた。
- **原因:** `refresh()` で `#edit-colors` と `#camera-colors` ボタンの `disabled` に `solving` が反映されておらず、また各モーダル起動ハンドラで探索の明示的な中断を行っていなかった。
- **修正内容:**
  - [`web/main.ts`](../web/main.ts): `refresh()` のセレクタに `#edit-colors` と `#camera-colors` を含め、`solving = true` の間はボタンを無効化。
  - [`web/main.ts`](../web/main.ts): `edit-colors.onclick` および `camera-colors.onclick` の冒頭で直ちに `stop()` と `cancelSearch()` を呼び出し、ダイアログ展開前に探索 Worker を安全に停止。
- **検証結果:**
  - 新規回帰テストにて、探索中にボタンが無効化されること、およびダイアログ起動時に探索 Worker が即時停止することを確認。

### F4 (P2): 解法自動再生中に Undo を呼んだ際の `playing` フラグ孤立スタック

- **問題:** 解法の自動再生中に Undo を実行すると、`stop()` が呼ばれず再生アニメーションと履歴巻き戻しが競合し、`playing` フラグが `true` のまま永久孤立して次回再生ボタンが反応しなくなる不具合。
- **原因:** `undo.onclick` が `stop()` を呼んでおらず、また `play()` 関数内の例外やループ終了時に `playing = false` が保証されていなかった。
- **修正内容:**
  - [`web/main.ts`](../web/main.ts): `undo.onclick` および `redo.onclick` で `stop()` を明示的に呼び出す。
  - [`web/main.ts`](../web/main.ts): `play()` 関数の再生ループを `try ... finally` 構造で囲み、ループ終了や例外発生時に確実に `playing = false` をリセットして `refresh()` を呼ぶように安全性を向上。
- **検証結果:**
  - 新規回帰テストにて、再生中に Undo を実行しても `playing` フラグが孤立せず、次回 `#play` ボタンを押した際に正常に再生が開始されることを確認。

### F5 (P3): 解法クローズボタン（`#solution-close`）押下時のフォーカス喪失（WCAG 2.4.3 / 2.4.7 違反）

- **問題:** キーボード操作で `#solution-close`（解法を閉じる）を実行すると、ボタン自身が非表示（`hidden = true`）になり、フォーカスが `document.body` に吹き飛んでフォーカスインジケータが消失していた。
- **原因:** `solution-close.onclick` で非表示化後のフォーカス遷移先が指定されていなかった。
- **修正内容:**
  - [`web/main.ts`](../web/main.ts): `solution-close.onclick` において、解法を閉じた直後に `$<HTMLButtonElement>("solve")?.focus()` を実行し、論理的な戻り先（「解法を探す」ボタン）へフォーカスを安全に移動。
- **検証結果:**
  - 新規回帰テストにて、`#solution-close` をクリックした直後に `document.activeElement` が `#solve` ボタンに遷移することを確認。
