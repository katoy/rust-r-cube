## 2. 指摘事項への対応詳細

### 2.1. High 指摘事項 (H1〜H3)

#### ✅ H1【カメラ入力】センター色による面付替処理のステッカー向き誤り
- **現象**: 撮影角度や照明によってセンター色を誤判定した際、面の割当先を動的に付け替える処理が存在したが、9マスの並び順（向き）が補正されず、展開図上で不正な配置になるリスクがあった。
- **対処内容**:
  1. 仕様（`docs/camera-input-spec.md`）の To-Be 構成に従い、幾何マッピングを固定化（View A: `U, R, F`、View B: `D, L, B`）。
  2. サンプリングされたセンター色が各面の想定色と異なる場合、UI上に「⚠️ センター色チェック: 一部のセンター色が期待と異なります」の明示的な警告を表示。
  3. `web/camera-geometry.ts` の `normalizeOutlinePoints` を強化。重心周りの偏角ソート後、最上部頂点（y 最小）を確実に P1（てっぺん）とする巡回シフトを適用し、反時計回り入力や微小な重心ノイズによるインデックスズレを完全解消。
- **検証**:
  `tests/camera-input.spec.ts`（全22テスト PASS）、および `tests/code-review-c7d4059-regression.spec.ts` で固定マッピング・警告表示・幾何正規化を検証。

#### ✅ H2【PWA / Service Worker】SW 更新後の Worker 再生成失敗・旧版タブ対応
- **現象**: SW 更新直後に旧版を開いたタブで解法のキャンセル・タイムアウト・「エンジンを再試行」等により Worker が再生成されると、旧ハッシュの Worker/WASM がキャッシュから削除されてロード失敗（`onerror`）となり、再読み込み案内も出なかった。
- **対処内容**:
  1. `web/solver-client.ts`: `readyPromise` および `waitForReady()` を実装。Worker 生成エラー（`isInitError`）と探索エラーを明確に分離し、エンジン初期化エラー時は直ちに検知可能にした。
  2. `web/main.ts`: エンジン初期化エラー発生時に `promptReloadForUpdate()` を呼び出し、ユーザーへ「新しいバージョンが利用可能です。再読み込みしてください」と明示的なリロード案内ダイアログを表示。
  3. `public/sw.js`: 自版キャッシュにリクエストされた資産が存在しない場合、既存の旧バージョンキャッシュ群（`cube-studio-*`）を探索してレスポンスする安全なフォールバック機構を導入。
- **検証**:
  `tests/code-review-c7d4059-regression.spec.ts` で `waitForReady` の挙動を検証、`tests/pwa.spec.ts` および `tests/infra-offline-regression.spec.ts` で SW 起動・オフライン動作を検証。

#### ✅ H3【ガードレール】静的チェッカーの検出漏れ改善
- **現象**: `scripts/check-review-guardrails.js` で `public/sw.js` の正規化キー保存パターンの検査が不完全で、レビュー指摘を見逃していた。
- **対処内容**:
  ガードレール検証スクリプトの正規表現パターンとルールを更新し、SW キャッシュキーのクエリ除去・canonicalKey 取り扱いの誤りを静的に検知できるように強化。
- **検証**:
  `npm run check:guardrails` PASS。

### 2.2. Medium 指摘事項 (M1〜M17)

#### ✅ M4【Rust 解法】cfop / thistlethwaite の無条件検証
- **現象**: `cfop.rs` および `thistlethwaite.rs` の解法検証コードに `#[cfg(debug_assertions)]` や `debug_assert!` が使われており、release ビルドで未検証の解を返すリスクがあった（原則 ① 違反）。
- **対処内容**:
  無条件の `if current != RawCube::default() { return Err(...) }` に置き換え、全ビルドプロファイルで確実に解の正当性を検証してエラーを返すよう統一。
- **検証**:
  `cargo test --release`（141 件 PASS）。

#### ✅ M5【Web 状態】共有 URL クエリのクリーンアップ
- **現象**: `?state=...` や `?alg=...` で共有された URL にアクセス後、ブラウザをリロードすると作業中の状態が破棄され共有局面に戻ってしまう。
- **対処内容**:
  `web/main.ts`: 初回ロード時に URL パラメータ（`state`, `alg`, `centers`, `solver`）を適用後、`history.replaceState` を用いてこれらのパラメータをアドレスバーからクリーンアップ（`?no-sw` などの環境フラグは維持）し、最新作業内容を `persist()`。
- **検証**:
  `tests/code-review-c7d4059-regression.spec.ts` でリロード時の作業状態保持を検証（PASS）。

#### ✅ M6【Web UI】探索タイムアウト後の再試行
- **現象**: 探索タイムアウト後の「30秒で再探索」ボタンを押した際、エンジンの再起動のみで探索自体がトリガーされないケースがあった。
- **対処内容**:
  `web/main.ts`: `solve(budget)` において、エンジンが準備未了または再起動中の場合は `await solver.waitForReady()` で確実にエンジンの初期化完了を待機してから探索処理を開始するように修正。
- **検証**:
  `tests/code-review-c7d4059-regression.spec.ts` で検証。

#### ✅ M7【Web 状態】`CubeStore.canRedo()` の実質差分判定
- **現象**: `canRedo()` が `future.length > 0` だけで判定されており、直前のスナップショットと実質的に同一の状態でも Redo ボタンが有効になっていた（原則 ② 違反）。
- **対処内容**:
  `web/cube-store.ts`: `canRedo()` において、`future` の末尾スナップショットと現在の盤面状態（`state`, `centers`）を比較し、実質的な差分が存在する場合のみ `true` を返すように変更。
- **検証**:
  `tests/code-review-c7d4059-regression.spec.ts` で検証（PASS）。

#### ✅ M8, M9【カメラ幾何】外周頂点の時計回り正規化と入力堅牢化
- **現象**: 頂点を反時計回りに入力した場合や、頂点削除後の再クリックで順序が崩れる問題。
- **対処内容**:
  - `web/camera-geometry.ts`: `normalizeOutlinePoints` を導入し、画面座標系における重心周りの角度順ソート＋最上部頂点（y 最小）を先頭にする巡回シフトで時計回り順序に統一。
  - `web/camera.ts`: ポインターイベントハンドラで `e.button === 0 && e.isPrimary` を検証し、主ボタン（左クリック）のみで頂点操作を受け付けるようガード。
- **検証**:
  `tests/camera-input.spec.ts` 全件合格。

#### ✅ M10【カメラ UI】読取面数に基づく適用ガード
- **現象**: 未読取の面でもステッカーを1枚タップすると読取済みにカウントされ、6面揃っていないのに適用できてしまう問題。
- **対処内容**:
  `web/camera.ts`: `capturedFaces: Set<string>` を導入。実際に画像からサンプリング・キャプチャされた面のみを登録し、進捗表示（`x / 6 面`）および「キューブに反映」ボタンの有効化（`capturedFaces.size === 6`）を厳格に管理。手動パレット編集も未キャプチャ面では無効化。
- **検証**:
  `tests/camera-input.spec.ts` で検証（PASS）。

#### ✅ M12【カメラ入力】巨大画像の事前拒否
- **現象**: 高圧縮 PNG など、ファイルサイズは小さくても展開時にギガバイト規模のメモリを消費する画像を読み込むとブラウザがクラッシュするリスク（原則 ③ 違反）。
- **対処内容**:
  `web/camera.ts`: `checkImagePixelCount` を実装。画像ファイルを `Image()` デコードする前に先頭 64KB のヘッダー（PNG / JPEG）をバイナリ解析し、幅×高さが 5000 万画素（50MP）を超える画像は即座に拒否してエラーを表示。
- **検証**:
  `web/camera.ts` の事前検証処理でガード。

#### ✅ M13【テスト基盤】偽陽性テストの解消
- **現象**: `test_r06_budget_contract`、`sw-update.spec.ts`、`code-review-125f8c8-regression.spec.ts` において、アサーションの漏れやモック不整合による偽陽性があった。
- **対処内容**:
  - `src/tests.rs`: `test_r06_budget_contract` に正しい superflip 文字列と経過時間（`elapsed >= budget`）のアサーションを追加。
  - `tests/sw-update.spec.ts`: オフラインナビゲーションテストに `await context.setOffline(true)` を明示的に追加。
  - `tests/code-review-125f8c8-regression.spec.ts`: 一時ディレクトリを用いて `checkInputsFreshness` のファイル追加・変更・削除を直接テスト。
- **検証**:
